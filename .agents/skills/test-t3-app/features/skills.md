# Skills inventory, Sources and Lab

Enter through panel picker K, its plus menu, palette Open skills/Install skills from git/
Create a skill, Settings > Tools and the optional loom.skill-registry.toggle keybinding.
Use an owned sandbox project and install only into its project skill roots. Provider
catalogs may be read from actual accounts; do not toggle/write their real homes.

Check account/scope/state filters, real paths, shared aliases, native enablement and
partial probe failures. Read-only providers/plugins/system skills must stay read-only.
Fetch a pinned public repository, observe phases and cancel, then fetch again. Inspect
scripts/licenses, install a complete folder and compare nested/binary files and modes.
An existing unmanaged destination must survive refusal.

Refetch a changed source and review files/text/binary differences. A stale review or
local modification must block replacement until a fresh explicit choice. Remove a
managed skill and verify its complete trash folder and recovery path. Never execute a
source's installer merely to verify copying.

Create a Lab skill, validate invalid and valid YAML, edit and save, then introduce an
external file change and prove conflict/reload or explicit overwrite. Switch tabs with
unsaved edits and preserve them. Choose a project and an available provider/model;
Test in new thread must open an unsent draft with the skill and sample prompt. Do not
spend a real model turn to prove draft creation. Check narrow panel and 390px layout.

Evidence: catalog visibility, pinned revision, target path, complete file comparison,
conflict/update/trash states and unsent test draft. Fixture service tests cover real
native Claude/Codex write protocols; a catalog read alone does not prove a toggle.
