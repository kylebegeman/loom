# Vault-backed work

Use Settings > Vault and its project connection selection, then the same capability from
a thread and an authorized bot/scheduled run. Distinguish missing metadata selection,
policy denial, locked/unavailable backend, host trust and upstream login. Never print
raw credentials or use production data as a fixture.

Use synthetic items and a sandbox broker/endpoint for denied, allowed, revoked and
rotated-version cases. The selected item/version and exact destination must remain
pinned; no silent fallback identity. A saved profile/reference is a requirement, not a
grant. Personal owner-trusted access does not authorize policy administration or reveal.

Inspect the resulting run outcome and recovery guidance on web and mobile. Cancel or
revoke access and prove no new credential use is authorized. Capture safe IDs/status
only, plus real client evidence of the missing/denied/recovery states. Exercise secret
input through request_secret/Vault; never enter a secret in chat or screenshots.
