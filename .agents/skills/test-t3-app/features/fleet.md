# Fleet placement and remote work

Use Settings > Computers and its linked-environment controls, plus Library project
launch and delegate_task when delegation is authorized. Both environments need the beta,
a working peer link and an eligible exact registered copy. Do not assume a canonical
upstream repository key identifies a Loom fork.

Choose explicit project/component/copy, host, branch and worktree where supported. Prove
those choices are honored or rejected with a useful error, and automatic placement
requires every required tool plus the selected provider. The remote Library binding
must exist before the first provider turn. Inspect history/project identity at both ends.

Retry the same accepted request, cancel pending/running work, reconnect and restart the
sandbox server. One request must not launch duplicate work, narrow permission ceilings
must hold, and remoteChild links/results must point to the destination environment.
Upstream rejects remote worktree isolation and nonempty forwarded uploads where
unsupported; do not turn those limitations into a claimed pass.

Evidence: both environment/build IDs, exact destination IDs, selected routes and modes,
request/task IDs, binding-before-dispatch, result link and cancellation/recovery outcomes.
If no second eligible computer is available, name that prerequisite and run the focused
LibraryDelegation/RemoteDelegation tests; those tests do not prove a real network trip.
