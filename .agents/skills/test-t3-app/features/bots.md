# Bots, engineering gates and intake

Open Bots from the sidebar or palette. Use the existing bot list, pipelines, run detail
and Needs you inbox as the action dashboard. Check typed input errors, permission denial,
pinned versions/model settings, budgets and archive/restore. Manual runs need authorization.

Exercise a bounded Review, fix, verify pipeline in an owned fixture checkout. Confirm
empty findings skip fixes, a real finding reaches one serialized fixer, verification
controls the next round and the round cap stops a nonconverging run. Cancel and resume
through the service/UI; retain the exact checkpoint and model identity.

For intake, validate signatures and duplicate delivery IDs before task creation. Triage
preserves source evidence/ownership and reproduction is read-only until a fix is
explicitly authorized. A bot run must be unable to dispatch another bot/thread/schedule.
Recurring review/performance/intake jobs use the existing trigger/schedule services,
with cooldowns, run budgets, inspectable outcomes and pause/resume.

Evidence: source revision, delivery/run IDs, pinned bots, verdicts, stop/recovery state
and duplicate/revoked rejection. Mock external provider boundaries when paid turns are
irrelevant; do not call an accepted webhook a completed engineering task.
