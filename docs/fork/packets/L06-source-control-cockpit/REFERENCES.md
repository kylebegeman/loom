## External

- varlock, [dmno-dev/varlock](https://github.com/dmno-dev/varlock), MIT. `varlock scan`
  (`packages/varlock/src/cli/commands/scan.command-spec.ts`, `scan.command.ts`): `--staged`
  scans `git diff --cached --name-only --diff-filter=ACMR`; default scans tracked plus
  untracked non-ignored files. It matches the project's resolved sensitive values as exact
  substrings, so it only finds values declared in the varlock schema, not arbitrary secrets.
  Findings print to stderr as `path:line:col KEY` with a redacted line; there is no JSON
  output; exit 1 for findings and for configuration errors alike; exit 0 when nothing is
  sensitive. Its `--install-hook` writes `<toplevel>/.git/hooks/pre-commit`, which does not
  work in a linked worktree (not used here). Unverified: behavior with a lone `.env` and no
  `.env.schema`, hence the `.env.schema` requirement.
- GitHub REST: check runs for a ref
  (https://docs.github.com/en/rest/checks/runs#list-check-runs-for-a-git-reference), combined
  commit status (https://docs.github.com/en/rest/commits/statuses), workflow job and job logs
  (https://docs.github.com/en/rest/actions/workflow-jobs).
- Git: `git status --porcelain=v2` unmerged entries
  (https://git-scm.com/docs/git-status#_unmerged_entries), `git log --topo-order`, sequencer
  state files (`rebase-merge/`, `rebase-apply/`, `MERGE_HEAD`, `CHERRY_PICK_HEAD`).
