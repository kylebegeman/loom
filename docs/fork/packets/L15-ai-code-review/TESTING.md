# L15 testing

Focused tests, no repo-wide checks, no sleeps: wait on deferreds tied to dispatched commands,
tool results or the reactor's own drain.

## Test doubles

- **Orchestration:** upstream's test orchestration engine (or a recording `dispatch`) that
  captures commands and lets a test emit domain events (`thread.session-set`,
  `thread.turn-diff-completed`, `thread.deleted`).
- **Jev:** a test layer for `LoomDecide` that returns scripted `DecideResult`s per feature
  (`answered` with answers, and `fallback` with each reason, including `low-confidence` with
  answers and a decision id) and records the requests it was given (EXTENSION-POINTS.md, section
  18, "Registering a packet", step 5). Its `settings` returns a feature view with a chosen
  threshold. TypeSafe is never called, and L15 tests do not reach `JevClient`.
- **Git:** a temporary repository with commits, a branch, uncommitted and untracked files;
  checkpoint refs created with `git update-ref` under `refs/t3/checkpoints/`.
- **impeccable:** a fake executable script in a temp directory named `impeccable` that
  records its argv and prints fixture JSON with a chosen exit code; `IMPECCABLE_BIN` points
  at it.
- **Persistence:** `SqlitePersistenceMemory`.

## Manual check (with Kyle's permission)

1. Thread with uncommitted changes containing a planted bug: start a review with Codex, then
   with Claude. Reviewer threads appear as "Review: ...", run, submit; the finding names the
   bug with the right file and line; the threads are settled afterwards.
2. Three reviewers (two models plus Auto): the dialog shows Auto's pick and confidence, the
   estimate says "3 reviewers, about 3 x ..."; the merged card says "Found by 2 of 3" for the
   planted bug.
3. "Fix this" and "Fix selected" add review comment chips to the source composer; nothing is
   sent; the findings show "Sent to fix".
4. Cancel a running review; the runs show "Cancelled" and submitted findings stay.
5. A reviewer that ignores the tool: fallback JSON works if present; otherwise "Ask again"
   recovers or the run fails clearly.
6. Turn, branch and commit targets; the diff panel button preselects the current scope.
7. A large turn shows the chip; with Jev removed, the threshold decides; "Start suggested
   reviews automatically" starts a small suggested review by itself and leaves a large one as
   a chip.
8. Agent tool with "Let agents use this" off (refused) and on (review starts, labeled).
9. impeccable lens on a UI change with the binary installed; lens hidden without it.
10. A reviewer asks for a command approval: "Waiting for approval", answered in its thread.
11. Upstream T3 server: every entry point hidden. Remote browser over Tailscale: start and
    read a review.

## Acceptance criteria

- Every flow, state and entry point in PRODUCT.md works on web and desktop, including the
  reverse of each action (cancel, dismiss and restore, dismiss suggestion, settings off).
- Findings reach the database only through the submit tool or the reviewer-thread fallback.
- No reviewer thread ever runs with a runtime mode other than `approval-required`.
- With no Jev key, or Jev timing out, every Jev-assisted path still completes through its
  fallback, and the UI names the fallback where the user chose Auto.
- Deleting a source thread removes its reviews and findings; deleting a reviewer thread does
  not remove findings.
- Loom never executes an `impeccable` subcommand other than `detect`.

## Merge safety

Merge preview against the newest nightly; after merge to `main`,
`scripts/fork/loom.sh integrate nightly --dry-run`.
