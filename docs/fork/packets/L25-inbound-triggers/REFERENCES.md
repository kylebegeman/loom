## Old Loom

Not a selections.md item; the brief notes old Loom's scheduled and webhook runs and its
Slack and Telegram gateways as Core-dependent references. Together they were about 20k
lines (triggers 2.4k, automation 4.6k, conversation gateways 8.7k, a Postgres scheduler
3.7k), much of it tied to old Loom's cloud Core (publicly reachable ingress, Postgres job
leases, a GitHub App credential broker).

## External

- withastro/flue at `5be3090` ([GitHub](https://github.com/withastro/flue)), Apache-2.0.
  "Channels" are verified inbound webhook routes per provider (`blueprints/channel.md`,
  `blueprints/channel--github.md`, `blueprints/channel--slack.md`,
  `packages/github/src/index.ts`, `packages/github/src/webhook.ts`) that turn a delivery into
  `dispatch(agent, { id, message, idempotencyKey })`. Borrowed ideas: one stable instance
  key per external object so later events continue the same session; the provider delivery
  id as the idempotency key; verify the signature over raw bytes before parsing; hand the
  agent a normalized message instead of the raw payload. No code is copied.
- GitHub REST: list issues assigned to the authenticated user
  (https://docs.github.com/en/rest/issues/issues#list-issues-assigned-to-the-authenticated-user),
  repository issues with `labels` and `since`
  (https://docs.github.com/en/rest/issues/issues#list-repository-issues), notifications and
  reasons (https://docs.github.com/en/rest/activity/notifications), workflow runs with
  `status` and `created` (https://docs.github.com/en/rest/actions/workflow-runs), workflow
  jobs (https://docs.github.com/en/rest/actions/workflow-jobs).
- GitHub webhooks: `X-Hub-Signature-256` validation
  (https://docs.github.com/en/webhooks/using-webhooks/validating-webhook-deliveries).
- `gh api` flags `-X`, `-f`, `--paginate` (https://cli.github.com/manual/gh_api).
- Unverified: whether `team_mention` notifications carry a usable `subject.url` for every
  subject type; handle null.
